# Cursor tasks

This file is the backlog for the workshop, admin board, developer page, and website-maker upgrades. The same file is in `website-maker` and `asoldi-website`. When a fact here changes, update both copies.

It is a map from research on 30 Sep 2026, not a promise that the code still matches. The chat that picks up a task re-reads the code, then asks the questions in that task before writing anything.

## How to run one task

Open a new chat in the repo that task names. Say which task id you want, and that the chat should research it again, switch to Plan mode, and ask the questions before any code. One task per chat. Do not start a second task in the same chat.

A task may land its own new files at any time. It may not rewrite a screen another task owns. Mount points are listed per task. If the screen you need to mount into is already being edited, stop and say so.

## Test loop

Every task runs three passes, and each failure changes the system.

- **Pass A** is local: unit tests, and a Docker or local UI walk of the same actions.
- **Pass B** is the first full walk on the deployed site. Use the real screen, not only a health check.
- **Pass C** is a second walk on that same deployed site: repeat the main action, then one extra case (refresh, a second client, or the undo path).

Deploy only after Pass A is green. The task is not done when it deploys. It is done when Pass B and Pass C are both green on the deployed site and no error from those passes is still open.

When a pass fails, do not only run it again. Change the code so that same error cannot happen again. The fix belongs in the system, not in a one-off for the test client, and it stays inside the locked behavior of that task. Add a check that fails if the error comes back. Then rerun from the pass that failed. If the failure was on the deployed site, deploy that fix before Pass B and Pass C run again. Repeat until both live passes are green.

## T01 — Workshop need-list

**Goal.** After a client is on the admin board, admin sees one living document: what is already done, what we already know, and what we still need from the client to finish the website. It is a tracking tool. It never writes logo, media, products, or any other client content into Kundedata, Maker, or the hub media library.

**Overlying step.** This is the preparation for the workshop, not the developer summary. The summary is T07 and stays empty until admin marks "Ha workshop".

**Build**

- A pure evaluator, `lib/workshop-needs.js`, that reads the sales client, the linked portal `clientDataBank`, the linked Maker run's domain and upload counts, stored Fireflies transcripts, sales notes, the offer (`meetingQuote`), and later the Gmail adapter. Return three lists plus counts:
  1. **Activity** — what has already happened (winner received, sales meeting held, offer sent, portal connected, workshop booked, and so on).
  2. **Already have** — facts we hold. Shown so admin can see them. Not phrased as questions to the client.
  3. **Still need from the client** — only gaps the client must still supply.
  4. **Could not tell** — a field we cannot score yet. Admin decides. Do not ask the client while it sits here. The chat that hits a real field in this bucket adds an evaluator for it instead of leaving it forever.
- Counts, with no green/red judgment: product count (items in `products` and `productCatalogs`), media count (sum of the media buckets, excluding empty strings). Five files can be enough. Fifty can be wrong. The document shows the number. It asks for media or products only when the count is 0 **and** the offer implies that kind of content (a menu, a catalog, a services list). A brochure offer with zero products is not a product request. When that call is uncertain, use "Could not tell".
- Binary gaps, asked only when empty everywhere we store them:
  - Logo: empty when `brandIdentity.logos.normal` and `media.logos` are both empty. This is the Kundedata logo, which is what admin means by the kunde terminal.
  - Domain: ask only when Maker `productionDomain` / `websiteDomain` **and** `websiteCreatorQuestions.websiteDomain` are all empty. If either side has a domain, do not ask. The green domain mark on the developer card is T09; this task only reads the same fields.
- Never ask the client for facts we already own. Treat these as "already have", even when the workshop has not happened yet: meeting time, online or in person, product notes, workshop start date, the new workshop clock time and format from T05, offer package / pages / services / one-time fees, sales notes, MyPhoner winner comment, how they found Asoldi, sales contact email, job title. Meeting time and workshop time are ours. They are not workshop homework.
