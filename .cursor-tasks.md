# Cursor tasks

This file is the backlog for the workshop, admin board, developer page, and website-maker upgrades. The same file is in `website-maker` and `asoldi-website`. When a fact here changes, update both copies.

It is a map from research on 30 Sep 2026, not a promise that the code still matches. The chat that picks up a task re-reads the code, then asks the questions in that task before writing anything.

## How to run one task

Open a new chat in the repo that task names. Say which task id you want, and that the chat should research it again, switch to Plan mode, and ask the questions before any code. One task per chat. Do not start a second task in the same chat.

A task may land its own new files at any time. It may not rewrite a screen another task owns. Mount points are listed per task. If the screen you need to mount into is already being edited, stop and say so.

## Test loop

Every task runs three passes, and each failure changes the system.

- **Pass A** is local: unit tests, and a Docker or local UI walk of the same actions.
- **Pass B** is the first full walk on the deployed site. Use the real screen, not only a health check.
- **Pass C** is a second walk on that same deployed site: repeat the main action, then one extra case (refresh, a second client, or the undo path).

Deploy only after Pass A is green. The task is not done when it deploys. It is done when Pass B and Pass C are both green on the deployed site and no error from those passes is still open.

When a pass fails, do not only run it again. Change the code so that same error cannot happen again. The fix belongs in the system, not in a one-off for the test client, and it stays inside the locked behavior of that task. Add a check that fails if the error comes back. Then rerun from the pass that failed. If the failure was on the deployed site, deploy that fix before Pass B and Pass C run again. Repeat until both live passes are green.
